MITM (Man-in-the-Middle) คือการโจมตีที่แฮกเกอร์เอาตัวเองเข้าไปแทรกอยู่ตรงกลางระหว่าง "เหยื่อ" กับ "ปลายทาง (เช่น เว็บไซต์ หรือ Router)" โดยที่ทั้งสองฝั่งไม่รู้ตัวเลยว่ากำลังสื่อสารผ่านแฮกเกอร์อยู่ เป้าหมายหลักคือการดักฟัง (Eavesdropping), ขโมยข้อมูล/รหัสผ่าน, หรือแอบแก้ไขข้อมูล

ในการโจมตีระดับสูง แฮกเกอร์มักจะไม่ใช้ท่าเดียว แต่จะใช้ 3 เทคนิคนี้ต่อเนื่องกันเป็นคอมโบ (Attack Chain):

1. ARP Spoofing (ปล้นทางเดินข้อมูลในวง LAN)
พฤติกรรม: โปรโตคอล ARP ไม่มีระบบยืนยันตัวตน แฮกเกอร์จึงส่งข้อความ (Gratuitous ARP) ไปหลอกเครื่องเหยื่อในวง LAN ว่า "MAC Address ของฉันคือ IP ของ Router นะ" ทำให้ข้อมูลทุกอย่างของเหยื่อวิ่งมาหาเครื่องแฮกเกอร์ก่อน

วิธีตรวจจับ (Detection):

ใช้ Wireshark กรอง arp.opcode == 2 (ดูเฉพาะ ARP Reply)

จุดสังเกตหลัก: พบการซ้ำซ้อน (Duplicate Mapping) คือมี MAC Address มากกว่า 1 อัน ที่อ้างตัวว่าเป็น IP ของ Gateway เดียวกัน

มีปริมาณแพ็กเก็ต ARP Reply โผล่มาเยอะและถี่มากผิดปกติ

2. DNS Spoofing (ป้ายบอกทางปลอม)
พฤติกรรม: เมื่อเหยื่อ (ที่โดน ARP Spoofing ไปแล้ว) พิมพ์ชื่อเว็บ (เช่น login.acme.com) แฮกเกอร์จะรีบชิงตอบกลับ DNS Query ก่อนเซิร์ฟเวอร์ของจริง โดยส่ง "IP ของเว็บปลอมที่แฮกเกอร์สร้างไว้" ไปให้เหยื่อ

วิธีตรวจจับ (Detection):

พบโดเมนที่เชื่อถือได้ (เช่น เว็บล็อกอินของบริษัท) แต่กลับถูก Resolve ไปยัง IP แปลกๆ (เช่น IP ภายในวง LAN หรือ IP ที่ไม่รู้จัก)

หากดูใน Log อาจพบ DNS Response 2 อันตอบกลับมาในเวลาไล่เลี่ยกัน (อันของแฮกเกอร์ตอบก่อน อันของจริงวิ่งมาทีหลัง)

3. SSL Stripping (กระชากเกราะป้องกัน)
พฤติกรรม: เมื่อเหยื่อหลงเข้ามาที่เว็บปลอม ปกติรหัสผ่านจะถูกเข้ารหัสด้วย HTTPS แต่แฮกเกอร์จะใช้เทคนิค "ดาวน์เกรด" การเชื่อมต่อของเหยื่อให้กลายเป็น HTTP ธรรมดา เพื่อให้เหยื่อกรอกรหัสผ่านส่งมาแบบไม่ได้เข้ารหัส

วิธีตรวจจับ (Detection):

พบทราฟฟิกเว็บเป็น HTTP (พอร์ต 80) ในหน้าเว็บที่ควรจะเป็น HTTPS บังคับใช้

หากวิเคราะห์ดูในเนื้อหาของ HTTP POST Request จะพบข้อมูลสำคัญ เช่น Username / Password ส่งมาเป็นตัวอักษรปกติ (Cleartext / Plaintext) ให้อ่านได้ทันที

🛡️ ตำแหน่งของ MITM ใน Cyber Kill Chain
หากโดนถามตอนสัมภาษณ์งานว่า MITM จัดอยู่ในขั้นตอนไหนของการโจมตี (Kill Chain) ให้ตอบว่า:

Exploitation (การเจาะระบบ): แฮกเกอร์เจาะผ่านช่องโหว่เชิงโครงสร้าง (ความเชื่อใจกันของโปรโตคอล ARP) เพื่อเอาตัวเองเข้าไปแทรก

Installation (การฝังตัว): เมื่ออยู่ตรงกลางได้สำเร็จ แฮกเกอร์สามารถใช้ตำแหน่งนี้ในการแอบยัดไส้ (Inject) มัลแวร์ไปกับไฟล์ที่เหยื่อกำลังดาวน์โหลด เพื่อฝังตัวลงในเครื่องเหยื่อต่อไป
